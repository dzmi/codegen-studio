# Правила разработки и работы с Codegen

## 1. Железные правила (что ломает систему)

1. **Для Python-файлов НИКОГДА не используй `replace_block` для функций или классов!** Используй `replace_symbol`. Приложению не нужно копировать старое тело функции, оно само найдёт его через AST. Это исключает 99% ошибок с несовпадением пробелов и экранирования.
2. **`replace_block` используй ТОЛЬКО для замены глобальных переменных, словарей или 1-2 строк кода.** Поле `old` должно быть коротким и уникальным.
3. **Для вставки нового кода используй `insert_before` или `insert_after` с КОРОТКИМ уникальным якорем** (например, `def existing_function():`). НЕ бери в качестве якоря длинный кусок кода.
4. **`create_directory` не требует, чтобы папка уже существовала.** Просто передай путь.
5. **Не генерируй гигантские JSON (>10 КБ).** Если нужно изменить весь проект, разбей задачу на несколько подзадач.

## 2. Как избежать ошибок при экранировании

- Двойные кавычки внутри JSON-строки: `\"`
- Обратные слеши: `\\\\`
- Переводы строк: `\\n`
- Если тебе нужно заменить длинный блок (например, конфиг), используй `create_file`, чтобы перезаписать файл целиком, а не `replace_block`.

## 3. Безопасность

1. **Любая запись файла — через `apply_simulation`.**
2. **`apply_simulation` — атомарна.** Если происходит ошибка, все изменения откатываются (`.bak`).
3. **Git commit** перед применением сложных изменений.
